# 引言

现在，我们要求解以下问题：

在一个带权有向图G中，给定源点start，求解start到达G中的其余各顶点的最短路径（假设G没有负权边）。

荷兰的一位计算机科学家E. W. Dijkstra于1956年，提出了一个求解以上问题的算法，算法的基本思想是按照路径长度递增的顺序，求得源点到其他顶点的最短路径。算法的过程如下：

结点分成两个集合：已确定最短路长度的点集（记为S集合）的和未确定最短路长度的点集（记为T集合）．一开始所有的点都属于T集合。

初始化dis[start]=0，其他点的dis均为+∞。

然后重复这些操作：

1. 从T集合中，选取一个最短路长度最小的结点，移到S集合中。
2. 对那些刚刚被加入S集合的结点的所有出边执行**松弛**操作。

直到T集合为空，算法结束。

以上算法就被叫做Dijkstra算法。

# 模拟

| 顶点            | 0     | 1    | 2     | 3    | 4    | 5    |
| --------------- | ----- | ---- | ----- | ---- | ---- | ---- |

| 已访问          | **T** | F    | F     | F    | F    | F    |

我们把2，4，5顶点下的dis和路径都更新了，但是为什么，我们只能确定2下的路径是最短路径呢？为什么此时的4，5不是最短路径呢？

因为0的出边只能到达2，4，5，如果0->2不是最短路径，那么一定存在0->4->?->2，或者0->5->?->2这样的路径，使得这条路径比0->2更短，但是不可能啊，在不带负权边的条件下，0->4和0->5就已经比0->2更大了。再带上别的顶点，一定会更大。因此，这就是使用Dijkstra算法，**不能有负权边的原因**。

0->4是不是最短路径？答案是不一定，根据以上的推理，是有可能存在一条0->2->？->4这样的路径，比0->4更短的。0->5也是同理。

我们结合定义来看，一开始0，1，2，3，4，5都属于T集合，然后我们取出0，是因为0此时dis最小，为0。然后我们把这个顶点加入到S集合，并且将这个顶点置为已访问，随后**找到这个顶点的所有的出边，并使用出边来更新到其他顶点的距离**。这就是松弛操作。

接下来的操作就是重复了，我们从所有未访问的顶点中，选出距离最小的那个顶点，将它的最短标记置为T，然后再将它加入S集合，并进行松弛。接下来我们取出顶点2。2的出边只能到3：

| 顶点            | 0     | 1    | 2     | 3       | 4     | 5    |

我们接下来完成代码编写，Dijkstra算法有朴素实现和优先队列实现两种方法。我们先完成朴素实现方法。

对于一个带权有向图G，我们假设有向图以邻接表给出，顶点数为n，边数为m。

假设以{{from1,to1,weight1},{from2,to2,weight2}}这样的形式给出，我们也可以进行以下操作进行建表：

```c++
vector<vector<int>> edges={{from1,to1,weight1},{from2,to2,weight2}};
vector<vector<pair<int,int>>> g(n);
for(auto e:edges) {
    int from=e[0],to=e[1],weight=e[2];
    g[from].push_back(make_pair(to,weight));
    // 无向图加以下这行
    // g[to].push_back(make_pair(from,weight));
}
```

在Dijkstra算法的朴素实现中，我们设置dis数组用于存储过程中的路径值，用vis数组存储顶点是否已访问，初始时start的dis值置为0，标记为未访问。其他节点以一个很大的数代表+∞。

由于每轮循环确定一个顶点的最短路径，需要循环n次，并且每次循环中，需要找出未访问点中路径确定为最短路径的点，所以需要一个二重循环。

朴素实现代码如下，我们使用c++完成以下代码：

```c++
vector<int> Dijkstra(vector<vector<pair<int,int>>> &g,int start,int n) {
    vector<int> dis(n,INT_MAX);
    dis[start]=0;
    vector<int> vis(n,0);
    for(int i=0;i<n;i++) {
        int u=-1,mind=INT_MAX;
        for(int j=0;j<n;j++) {
            // 找当前未访问的点中，dis最小的确定为最短路径
            if(vis[j]==0&&dis[j]<mind) {
                u=j;
                mind=dis[j];
            }
        }
        // 如果最后一个点的最短路径为INT_MAX,则不用这个点更新其他顶点了，因为这种情况代表达不到
        // 这就是以上例子中的最后一步的情况
        if(u==-1) continue;
        vis[u]=1;
        // 松弛：用这个顶点的出边更新到其他顶点的最短路径
        for(auto e:g[u]) {
            int to=e.first,wt=e.second;
            if(dis[to]>dis[u]+wt) {
                dis[to]=dis[u]+wt;
            }
        }
    }
    return dis;
}
```

在以上算法中，我们遍历顶点的时间复杂度为O(n^2)，松弛操作处理所有的边，时间复杂度为O(m)，所以总的时间复杂度为O(n^2+m)，一般我们写作O(n^2)。

使用优先队列优化的Dijkstra算法则更好理解，我们建立一个小顶堆，每次将更新后的dis值和顶点插入优先队列，想取出最小的dis值和顶点时，只需要取堆顶元素就可以了。

代码如下：

```c++
vector<int> Dijkstra(vector<vector<pair<int,int>>> &g,int start,int n) {
    vector<int> dis(n,INT_MAX);
    priority_queue<pair<int,int>,vector<pair<int,int>>,greater<pair<int,int>>> pq;
    dis[start]=0;
    // 按照dis,n的顺序，堆会按照第一个元素来排序
    pq.push(make_pair(0,start));
    while(!pq.empty()) {
        auto [disX,pos]=pq.top();
        pq.pop();
        // 如果这个点之前已经松弛过，则跳过这个点
        if(disX>dis[pos]) continue;
        for(auto e:g[pos]) {
            int to=e.first,wt=e.second;
            if(disX+wt<dis[to]) {
                dis[to]=disX+wt;
                pq.push(make_pair(dis[to],to));
            }
        }
    }
    return dis;
}
```

使用堆优化的缺点是，一个顶点可能多次入堆，结合一下我们之前的例子，在第4，5步我们都更新了顶点5的dis值，那么这个顶点5就需要进堆两次。在朴素实现中，我们一轮循环可以确定一个顶点。

我们分析一下这个算法的时间复杂度，松弛操作中，遍历每条边并插入顶点，最坏情况下每条边都插入它的to顶点，堆的插入操作是log级别的，所以这里的时间复杂度为O(mlogm)。

是不是堆优化Dijkstra算法的时间复杂度一定优于朴素实现？答案是错误的。实际上，朴素实现适用于稠密图，堆优化适用于稀疏图，这是因为在稠密图情况下，m≈n^2，此时堆优化的时间复杂度为O(n^2logn)，就会不如朴素实现。

如何求解一个带权有向图任意两点之间的最短距离？只需要对每个点为源点执行一次Dijkstra算法就可以了，当然前提是没有负权边。
